# 証明の短縮

検証(このリポジトリの本来の目的)のあとに取り組む、2 つ目の目標です。配布された Lean 証明
(**175,187 ファイル・17,374,215 行・約 1.03 GB**)を、主張を変えずにどこまで短くできるかを調べます。
2026-11-22 に始めました。

## 守ること

- 主張は変えない。`Statements.lean`(検証者の命題と一致することを確かめたもの)と、`Main.lean` の主定理 5 件はそのまま残す。
  短くした版にも、検証と同じ検査(ビルド、`#print axioms`、主張の一致、カーネル再検査)をかける。
- 原本 `evidence/` と、検証に使っている `lean/` は書き換えない。短縮版は別の場所に写して作る
  (`lean/` のソースは、検証の最後のソース不変確認の対象)。
- 配布物にも PDF にもライセンスの表示がないため、短縮版のソースそのものは公開しない。公開するのは、
  短縮の手順(スクリプト)、消した宣言やまとめた宣言の一覧、規模の数字。
- 検証の常駐プロセスが動いているあいだは、重い処理を `nice` で優先度を下げて走らせる。

## 段階

1. 機械的な短縮
   1. 使われていないものを消す。主定理の証明項から辿れない宣言と、そういう宣言しか入っていないモジュール。
   2. 明らかな重複をまとめる。型が同じ定理、型も値も同じ定義、別の定理をそのまま返すだけの定理(別名)。
   3. Mathlib にあるものを置き換える。Mathlib(と Lean 本体・Batteries)に同じ型の定理があるもの。
2. 数学的な短絡。証明の筋道そのものに近道がないかを探す。1. で残った骨格を読んで考える。

段ごとに短縮版をビルドし直し、検査を通してから次の段へ進みます。

## 規模の測り方

README の「Lean コードの規模」と同じ数え方(`.lean` のファイル数・行数・バイト数)に宣言の数を加えて、
段ごとの減り方を記録します。

## 下調べ: どの宣言が実際に使われているか

`scripts/shorten_analyze.sh` が、Lean で書いた解析ツール [`tools/rhshrink`](tools/rhshrink/Main.lean) で次を調べます。
配布物のビルド結果(`.olean`)を読み込むだけなので、検証と並行して走らせられます。

- 主定理 5 件から、型と値(証明項)に現れる定数を推移的に辿る。配布物の各宣言を、次の 3 つに分ける。
  - `live`: 宣言の定数そのものが使われている
  - `aux`: 宣言そのものは使われていないが、その補助定数(`foo.match_1` など)だけが別の宣言から使われている
  - `dead`: 使われていない
- Lean がビルド結果に残している宣言の位置(行範囲)から、使われていない行数をモジュールごとに数える。
- 使われている定理のうち、型が同じものの組(重複)、外部(Mathlib など)に同じ型の定理があるもの、別名を挙げる。
  型は、宇宙レベルとメタデータを消してから α 同値で比べる。

これはカーネルの項の上での解析です。エラボレーションのときにだけ使われるもの(notation、マクロ、
証明項に痕跡を残さない `dsimp` 用の rfl 補題など)は数えていません。「使われていない」と出た宣言を
本当に消せるかは、消したソースをビルドし直して確かめます。

出力(`/var/tmp/riemann-hypothesis-ywr/runs/shorten/analysis-<時刻>/`)

| ファイル | 中身 |
